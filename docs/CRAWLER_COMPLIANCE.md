# 爬虫合规提醒 + 安全漏洞清单

> 本文件是硬性约束落地文档。仓库内任何爬虫脚本**仅供本地测试**，禁止用于商业抓取。

## 一、爬虫合规提醒

### 1. 法律法规风险
商业部署爬虫可能触及：
- 《网络安全法》：干扰网络正常运行、未授权访问。
- 《数据安全法》：未经许可收集/处理数据，重要数据出境。
- 《个人信息保护法》：抓取姓名/证件号/联系方式等属违法处理个人信息。
- 《刑法》285/286 条：非法获取/破坏计算机信息系统数据。
- 高校网站使用条款/robots.txt：违反可构成违约或不正当竞争。

### 2. 本项目硬性合规约束
| 约束 | 落地 |
|------|------|
| 必须设置访问延时 | 单线程 + 随机 2~5s 延时，写 crawl_logs.delay_seconds |
| 禁止暴力并发 | 并发=1，无多线程/协程批量 |
| 不抓取/存储考生姓名隐私 | PDF 解析跳过姓名列，不入库；user_score_reports 无姓名字段 |
| 仅抓公开数据 | 白名单域名（高校研究生院官网）+ 公开发布名单 |
| 遵守 robots.txt | 启动前拉取并缓存，禁止路径跳过 |
| 标识来源 | User-Agent 含联系方式；每条数据带 source_url |
| 失败退避 | 429/503 指数退避，最多 3 次 |
| 可审计 | 全量写 crawl_logs |

### 3. 商业化前必须完成
- [ ] 取得数据来源授权或确认公开数据可合规聚合
- [ ] 个保法/数据安全法评估并出具报告
- [ ] ICP 备案 + 小程序资质
- [ ] 爬虫改造为授权 API 优先，爬虫仅作兜底
- [ ] 用户数据采集前完成《隐私政策》《用户协议》
- [ ] 删除/限制本地测试爬虫的生产路径

## 二、潜在安全漏洞清单（按模块）

### A. 鉴权与会话
1. **JWT 密钥硬编码/弱密钥** → 泄露可伪造任意用户。缓解：环境变量注入、≥32 字节随机、定期轮换。
2. **refresh token 不可吊销** → 登出后仍可用。缓解：refresh 存 Redis，吊销即删。
3. **微信 code 重放** → code 一次性，但未校验已用会导致重放。缓解：Redis 标记 code 已用 5min。
4. **session_key 泄露** → 可解密用户数据/伪造。缓解：不持久化或加密短期存储。
5. **openid 伪造** → 前端直传 openid 当身份。缓解：仅服务端 code2session 换取，禁前端传 openid。

### B. 接口与越权（IDOR）
6. **IDOR 查看他人填报/订单** → `/reports/{id}` 不校验归属。缓解：查询带 `user_id=current`。
7. **VIP 鉴权绕过** → 仅前端隐藏按钮。缓解：后端 `require_vip` 装饰器 + audit_logs。
8. **枚举遍历** → school_id/major_id 自增可遍历。缓解：限流 + 必要时改用哈希 ID 对外。
9. **未限流** → 登录/检索被爆破/爬取。缓解：Redis 滑窗限流。

### C. 注入与解析
10. **SQL 注入** → 拼接 LIKE/排序。缓解：全程参数化/ORM，禁 f-string 拼 SQL。
11. **PDF 解析致内存炸/恶意 PDF** → 大文件/构造 PDF。缓解：文件大小上限、沙箱解析、超时。
12. **SSRF（爬虫 URL）** → 抓取内网/元数据。缓解：URL 白名单（高校域名）+ 禁私网 IP + 禁 file://。
13. **XXE** → 若用 XML 解析。缓解：禁用 DTD（本项目以 PDF 为主，仅作提醒）。

### D. 数据泄露与脱敏
14. **填报记录泄露身份** → 返回 user_id/昵称。缓解：对外 DTO 剔除 user_id。
15. **错误信息泄露** → 堆栈/SQL 回显。缓解：统一错误处理，生产关闭 debug。
16. **日志泄露敏感数据** → 打印 token/分数。缓解：脱敏日志规范。

### E. 前端与小程序
17. **XSS（昵称/参考书）** → 富文本未转义。缓解：输出转义，小程序 rich-text 限域。
18. **越权前端校验** → 仅前端判断 VIP。缓解：以接口 403 为准。
19. **小程序包体积/敏感 key** → AppSecret 入包。缓解：AppSecret 仅后端，前端不带。
20. **HTTPS 缺失** → 小程序强制 TLS。缓解：Nginx + 合法证书 + 域名备案。

### F. 基础设施
21. **MySQL/Redis 暴露公网** → 默认端口+弱口令。缓解：仅内网/容器网络，强密码，防火墙。
22. **依赖漏洞** → 第三方包 CVE。缓解：requirements 锁版本 + 定期 audit。
23. **备份泄露** → 备份含真实数据且明文。缓解：加密存储 + 访问控制。
